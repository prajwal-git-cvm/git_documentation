02

Track Files

Choose which changes Git should include in the next commit.

Check untracked files

Terminal
git status

Untracked files are files Git knows about but is not tracking yet.

Add a specific file

Terminal
git add config.js

Add a folder

Terminal
git add src/

Add all changes

Terminal
git add .

Stages changes in the current directory and its subdirectories.

Unstage changes

Terminal
git reset
git reset config.js

The first command unstages all staged changes. The second unstages only config.js. Your working files remain unchanged.

Modify the Previous Commit

Amend the most recent commit.

Amend the previous commit

Terminal
git add .
git commit --amend -m "Updated commit message"

Replaces the previous commit with a new one containing the staged changes and updated message.

Heads up: Amending changes the commit ID. Avoid amending commits already shared with others unless you understand the effects.

07

Restore Changes

Unstage files or discard local edits.

Restore a file from staging

Terminal
git restore --staged config.js

Unstages the file but keeps its changes in your working directory.

Discard changes in a file

Terminal
git restore config.js

Restores the file from the staging area, or from the last commit if it is not staged.

Warning: This can permanently discard uncommitted changes.

Restore all tracked files in the current directory

Terminal
git restore .

Restore a file from an older commit

Terminal
git restore --source=<commit-id> -- config.js

# Example: restore from the previous commit
git restore --source=HEAD~1 -- config.js

Restores that file without moving the current branch.

Switch Between Commits

Inspect a past snapshot or move between branches.

Switch to a specific commit

Terminal

# Example
git checkout a1b2c3d

Lets you view the project at that commit.

Return to the main branch

Terminal
git checkout main

Use the newer switch command

Terminal
git switch main
git switch -

The first switches to main; the second returns to the previous branch.

Understand Detached HEAD

A detached HEAD means you checked out a commit directly, not a branch.

Enter detached HEAD state

Terminal

You can inspect the project and experiment. New commits made here are not automatically connected to a branch.

Create a branch to keep your work

Terminal

Creates a branch at the current commit and switches to it.

Keep an existing detached commit

Terminal

Creates a branch that points to that commit.

Bring old file contents into your current working tree.

Restore all tracked files from a commit

Terminal

Terminal

16

Merge Branches

Combine changes from one branch into another.

Merge a feature branch into main

Terminal
git switch main
git merge feature1

Switches to main and merges changes from feature1 into it.

Fast-forward merge

Happens when the receiving branch has no new commits since the feature branch was created.

Before:

A---B---C (main)
         \
          D---E (feature1)

After:

A---B---C---D---E (main)

Git simply moves the branch pointer forward. No merge commit is created.

Three-way merge

Happens when both branches have new commits.

Before:

A---B---C---F (main)
         \
          D---E (feature1)

After:

A---B---C---F---M (main)
         \       /
          D---E

Git creates a merge commit (M) that combines both histories.

Merge without fast-forward

Terminal
git merge --no-ff feature1

Creates a merge commit even when a fast-forward merge is possible.


17

Merge Conflicts

Understand and resolve conflicts when Git cannot automatically combine changes.

Check conflicting files

Terminal
git status

Shows files that have merge conflicts.

Understand conflict markers

<<<<<<< HEAD
Change from main
=======
Change from feature1
>>>>>>> feature1
  • HEAD represents the current branch.
  • ======= separates the two versions.
  • feature1 represents the incoming branch.

Choose the current branch version (ours)

Terminal
git checkout --ours filename.txt
git add filename.txt

Keeps the current branch version of the file.

Choose the incoming branch version (theirs)

Terminal
git checkout --theirs filename.txt
git add filename.txt

Keeps the incoming branch version of the file.

Complete the merge

Terminal
git add filename.txt
git commit

After resolving all conflicts and staging the files, complete the merge commit.

Cancel the merge

Terminal
git merge --abort

Attempts to return the working tree to its state before the merge started.


18

Delete Branches

Remove local or remote branches that are no longer needed.

Delete a merged local branch

Terminal
git branch -d feature1

Safely deletes the branch if Git considers it merged.

Force-delete an unmerged branch

Terminal
git branch -D feature1
Warning: This deletes the branch even if it contains unmerged commits.

Delete a remote branch

Terminal
git push origin --delete feature1

Deletes the branch from the remote repository, such as GitHub.

Clean up deleted remote branches

Terminal
git fetch --prune

Removes outdated remote-tracking references for branches deleted from the remote.

Note: You cannot delete the branch you are currently using. Switch to another branch first.

19

Rename Branches

Change the name of an existing local or remote branch.

Rename the current branch

Terminal
git branch -m new-name

Renames the branch you are currently using.

Rename another local branch

Terminal
git branch -m old-name new-name

Renames the specified local branch without switching to it.

Rename a remote branch

Git does not directly rename a remote branch. Rename your local branch and push the new name.

Terminal
# Rename the local branch
git branch -m old-name new-name

# Push the new branch name
git push -u origin new-name

# Delete the old remote branch
git push origin --delete old-name

This creates the new remote branch and removes the old one.


20

Branch History

Understand how branches and commits are connected over time.

How branch history works

Git branches are pointers to commits. Creating a branch does not copy the entire project. It creates a new pointer to the current commit.

A---B---C (main)
         \
          D---E (feature1)
  • A, B, C are commits on the main history.
  • feature1 starts from commit C.
  • D, E are new commits on the feature branch.
  • Both branches share their earlier commit history.

Branches after merging

A---B---C---F (main)
         \     \
          D---E---M

A merge connects the histories of the branches. The resulting history contains the commits from both branches.

Important points

  • Every commit has a unique hash.
  • A branch points to a commit.
  • New commits move the current branch pointer forward.
  • Deleting a branch does not automatically delete its commits.
  • Merging combines branch histories.

21

Common Branch Mistakes

Understand common mistakes when working with Git branches and how to avoid them.

1. Merging into the wrong branch

Problem: Running merge while on the wrong branch.

Solution: Switch to the branch that should receive the changes first.

git switch main
git merge feature1

2. Deleting an unmerged branch

Problem: Using force deletion without checking for unmerged commits.

Solution: Check branch history before using -D.

git log main..feature1 --oneline

3. Working directly on main

Problem: Making feature changes directly on the main branch.

Solution: Create a separate feature branch.

git switch -c feature1

4. Forgetting to push a new branch

Problem: A local branch does not automatically appear on GitHub.

Solution: Push it to the remote repository.

git push -u origin feature1

5. Deleting the current branch

Problem: Trying to delete the branch you are currently using.

Solution: Switch to another branch before deleting it.

git switch main
git branch -d feature1

6. Forgetting to check branch status

Problem: Making changes without knowing which branch is active.

Solution: Check your current branch and working tree.

git status
git branch

View Branch History

Use Git log commands to inspect commits and visualize branch history.

View current branch history

Terminal

Displays commit history in a compact format.

View history of all branches

Terminal

Displays commits from all branches.

View branch history as a graph

Terminal

Shows branch connections, commits, and branch names in a visual text graph.

Example:

*   a1b2c3d (HEAD -> main) Merge feature1
|\
| * e4f5g6h (feature1) Add new feature
* | i7j8k9l Fix a bug
|/
* m1n2o3p Initial commit

View branches and their latest commits

Terminal
git branch -v

Displays local branches with their latest commit information.

Remember

Quick revision of important Git branching commands.

  • git branch lists local branches.
  • git switch switches between branches.
  • git switch -c creates and switches to a new branch.
  • git merge combines changes from another branch.
  • git merge --abort cancels an unfinished merge.
  • git checkout --ours selects the current branch version during a conflict.
  • git checkout --theirs selects the incoming branch version during a conflict.
  • git branch -d safely deletes a merged branch.
  • git branch -D force-deletes a branch.
  • git branch -m renames a branch.
  • git push -u origin branch-name publishes a branch to GitHub.
  • git push origin --delete branch-name deletes a remote branch.
  • git log --all --graph --oneline displays branch history.

Understand HEAD and Commit References

Use HEAD to identify the current position in your repository.

Show the current commit

Terminal

Show the previous commit

Terminal
git show HEAD~1

Show two commits before HEAD

Terminal
git show HEAD~2

Show the current HEAD reference

Terminal
git rev-parse HEAD

Understand commit references

HEAD – Current commit.
HEAD~1 – One commit before HEAD.
HEAD~2 – Two commits before HEAD.
HEAD^ – First parent of the current commit.

Understand Merge Conflict Sides

Choose which version of a file to keep when a merge conflict occurs.

Understand Ours and Theirs

Ours – Changes from the currently checked-out branch.
Theirs – Changes coming from the branch being merged.

Keep the current branch version

Terminal
git checkout --ours src/main.c

Keep the incoming branch version

Terminal
git checkout --theirs src/main.c

Apply to all conflicting files

Terminal
# Keep current branch versions
git checkout --ours .

# Keep incoming branch versions
git checkout --theirs .

These commands select one side's version and discard the other side's conflicting content for the selected files.

Complete conflict resolution

Terminal
git add src/main.c
git commit -m "Resolve merge conflict"

Stage the resolved files and create a commit to complete the merge.

Reset – Move Branch History

Move the current branch to an earlier commit with different reset modes.

Undo a commit but keep changes staged

Terminal
git reset --soft HEAD~1

Undo a commit but keep changes unstaged

Terminal
git reset --mixed HEAD~1

Undo a commit and discard changes

Terminal
git reset --hard HEAD~1

Reset to a specific commit

Terminal
git reset --hard <commit-id>

Understand reset modes

--soft – Moves HEAD but keeps changes staged.
--mixed – Moves HEAD and unstages changes.
--hard – Moves HEAD and resets tracked files.

Warning: The hard reset can permanently discard uncommitted changes.

Bisect – Find Which Commit Introduced a Bug

Terminal

Terminal

Mark a known working commit

Terminal

Terminal
